## Description

In the standalone Photino desktop app, clicking a link in a record (markdown
links, rendered with `target="_blank"` in `markdown.js:161`/`:169`) or in Help
(`help_service.js:112`) should open the system's default browser. It doesn't:
the app does nothing to route it there, so the result is whatever Photino's
webview does by default.

Found: nothing handles navigation, `window.open` or new-window requests.
`NativeBridge.cs` only offers window ops and `dialogs.saveFile`, so there is no
`shell.openExternal`. Fix: add an `openExternal` bridge call (`Process.Start`
with `UseShellExecute = true` on Windows, `xdg-open` on Linux, `open` on macOS),
allow only http(s)/mailto, and route external link clicks and `window.open`
to it whenever the native host is present. In the browser build, links keep
opening in a new tab.

### 2026-10-16T11:38Z · norman_agent (status: investigation -> testing)

Fixed in 4b96de4 (on main), through FlexDesk 0.16.0 (FlexDesk STORY-0027,
`../FlexDesk/backlog/STORY-0027.md`):

- the host port has a new `shell.openExternal(url)` capability, which
  `createPhotinoHost` offers
- `routeExternalLinks({ host })` sends `_blank` links, links to other origins,
  mailto, middle clicks and external `window.open` calls to it
- `NativeBridge.cs` answers `shell.openExternal`: `UseShellExecute` on Windows,
  `xdg-open` on Linux, `open` on macOS, and **only for http, https and mailto**,
  because the URL comes from record text. Anything else is refused, and the
  page falls back to `window.open`.
- in a browser tab nothing changes (that host has no `shell`)

Verified in the real desktop app (built from the fix, isolated
BUGDESK_DESKTOP_HOME, over CDP):
- `describe` lists `shell`
- `file:///C:/Windows/notepad.exe`, `javascript:`, `ms-settings:` and a non-URL
  are all refused
- a `target="_blank"` https link and a `window.open` of an external address both
  reached `shell.openExternal`, with no navigation and no new webview window

I did not let it actually launch your browser during the test. **Please click
one link in a record in the desktop app**: it should open in your default
browser. The desktop app needs a rebuild to pick up the NativeBridge change.
