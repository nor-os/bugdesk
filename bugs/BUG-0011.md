## Description

Reported by norman: *"data products: map seems disproportionally large - and the style is quite
bad"* and *"find a better way of displaying collections in general. the current illustration looks
poor."*

The Map view replaced the whole registry table with a FlexDesk `TreeView` stretched across the tile
(~1,300px for three folders, counts pushed to the far edge), and every icon overflowed its 14–18px box
because Google's `.material-symbols-outlined { font-size: 24px }` loads last and wins. To see what a
folder holds you had to leave the table that can sort, filter and open products.

## Comments

### 2026-09-23T19:00Z · norman_agent (status: investigation -> testing)

Replaced the Map view with a **collections navigator beside the table**
(`web/js/governance/collection_tree.js`, rewritten; `products_pane.js`; `tables.css` `.tbl-colnav*` /
`.tbl-colsplit*`, the dead `.tbl-map` and `.tbl-grid__views` rules removed).

- A 220px folder column using the house sidebar (`.tbl-projsettings__sidebar` / `__item`): All
  products, the nested folders with a chevron to fold and a rolled-up count, then Uncollected.
- Picking a folder narrows the table to that folder and everything below it. The Collection column
  now shows the full path (`Finance › EMEA › Sales`).
- The toolbar's List/Map toggle is now a **Collections** toggle that shows or hides the column,
  remembered per browser. The new-folder button sits in the column's own header; right-click menus
  are unchanged.

Verified: `governance/render.test.mjs` GREEN with new assertions (beside the table, house sidebar
item, nesting, rolled-up count, folder narrows table, name written as text, chevron folds without
changing the selection). Screenshotted in headless Edge against the running stack.

**The fix is in the Tables working tree and not yet committed.** The frontend is bind-mounted, so it
is live on a reload.
