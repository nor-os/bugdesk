## Description

Any row whose `description` field contains a comma gets silently truncated at
the first comma when exported to CSV — the rest of that field, and every
column after it in that row, is lost. Doesn't error, doesn't warn, just quietly
wrong data in the downloaded file.

## Comments

### 2026-07-11 · reviewer

Found this because a monthly export was missing data that's definitely in the
app. Compared row counts — same number of rows, just truncated columns on the
affected ones.

### 2026-07-26 · agent

Confirmed: the CSV writer does a plain `values.join(',')` with no quoting or
escaping at all. Any field containing a comma breaks the column alignment for
that row (not just that field — everything shifts left by one column from
that point on, since the reader has no idea the comma was part of the data).

Fix: quote every field and escape internal double-quotes per RFC 4180
(`"like, this"` becomes `"""like, this"""`... well, `"like, this"` — the
field wraps in quotes and any `"` inside doubles up). Applied it to the
export writer. Also added a quick regression check: every field with a comma,
a quote, or a newline in it now round-trips through export → re-import
correctly.

### 2026-07-27 · agent

Status → testing. Should be safe to verify against the same monthly export
that originally surfaced this.
