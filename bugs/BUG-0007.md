## Description

Any username with accented characters or non-Latin script (reported so far:
"Müller", "José", and one report with a Cyrillic name) fails login with a
plain 500 error page instead of either working or showing a friendly
validation message.

## Comments

### 2026-07-06 · reviewer

Third report this week, all non-ASCII usernames. Definitely affects real
users, not an edge case.

### 2026-07-20 · agent

Traced it to the username lookup, which normalizes input with a
Latin-only regex before hitting the database — anything outside that range
gets mangled into an empty string, and the empty-string lookup path wasn't
handling "user not found" cleanly, hence the 500 instead of a normal
"invalid credentials." Fix: switch the normalization to Unicode-aware
(NFKC normalize, then compare) instead of stripping to ASCII. Usernames with
diacritics and non-Latin scripts now round-trip correctly through signup and
login in my local testing.
