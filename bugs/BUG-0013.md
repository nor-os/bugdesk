## Description

Reported by norman: *"clicking governance should open a fresh tab-rail: each category / major
page hosts their own tab-rail, they do not share one."*

Top-nav pages each had their own desktop, but Governance's categories (Data products, Lineage,
Sources, Change log, per scope) shared one. So a product opened from the registry sat in the same
strip as Lineage, and clicking a category in the rail went through `openInPrimary`, which REPLACED
the active tab — the product you had open was thrown away.

## Comments

### 2026-09-23T19:00Z · norman_agent (status: investigation -> testing)

Each Governance category now gets its own FlexDesk desktop, so its own tab strip
(`web/js/shell/tables_shell.js`: `governanceDeskFor`, `enterGovernanceDesk`, `stayInGovernance`,
`enterDeskIndex`; `showGovernancePane` rewritten).

- The default category (Data products in the current scope) keeps the page's own desktop, so the
  Governance rail icon and the Data products row show the same strip.
- The other categories get desktops allocated after the pages, so no page's index or Alt+digit
  moves. A new desktop is seeded before the switch, so the Tables overview never mounts on it.
- A category click ACTIVATES its root tab (or opens one if it was closed) instead of replacing
  the active tab, so an open product survives.
- Open-in-tab / split / float from a category's menu act on the Governance desktop you are on.

Verified in headless Edge: open a product with one click → Lineage → Data products → Data products
(org) → Lineage → Tables page → Governance. Each step showed the right tile title, and at the end
the Data products strip still held both "Bursary analysis" and "Data products". All shell suites
GREEN, though none of them exercises Governance placement. Uncommitted in the Tables working tree.
