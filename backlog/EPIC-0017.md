## Description

Make what happens to a ticket configurable instead of hard-coded. Two parts:
- the built-in workflow moves (Start investigation, Hand to testing, Close, the
  backlog ladders) become data a project can change, including what a move does
  on the side, e.g. clearing the assignee
- new custom actions and alerts are built from the same steps

This builds on EPIC-0003: actions and alerts work on any field, custom ones
included.

## Acceptance criteria

- [ ] A project can change what the built-in moves offer and do, including side effects like clearing the assignee (STORY-0018)
- [ ] A project can define its own actions from the same steps (STORY-0007)
- [ ] Alert rules notify the open BugDesk when records start matching them (STORY-0005)
