## Description

A **Dashboards** section in the top bar, next to Tracker, so a project can see its work as charts instead of
lists: how many bugs are open by severity, where the points are, what is left in a phase and whether it will be
done by its date. Dashboards are per project. They can chart any attribute of a bug, backlog item or tracker
record, custom fields included. Grouping and counting work on any field; sums, averages and histograms only on
numeric ones. The burndown chart is required.

Shared dashboards are committed with the project, and everyone on the repo sees the same ones. Each person can
also keep personal dashboards that only they see. The example project ships a Bugs dashboard and a Backlog
dashboard.

Built on FlexDesk, not beside it (FlexDesk-first). The grid is `@flexdesk/tiles`
(TileGrid, already in the vendored 0.12.1), the charts are `@flexdesk/charts` over Plotly, and the generic chart
and KPI tiles are FlexDesk's part: FlexDesk EPIC-0021 / STORY-0022 (`../FlexDesk/backlog/STORY-0022.md`).
BugDesk's part is the section, the storage, the data (records → series, including History → burndown) and the
defaults.

Known limit: History records status, assignee and reporter, not points, so a points burndown uses each item's
*current* estimate. A re-estimate changes the past of the chart. The chart says so. Recording points history is
deliberately out of scope.

## Acceptance criteria

- [ ] Dashboards appears in the top bar of every project, and its shared dashboards are committed with the project (STORY-0034)
- [ ] A person can keep personal dashboards next to the shared ones, and can copy one into the other (STORY-0035)
- [ ] A tile can chart any bug or backlog attribute, custom fields included, filtered to a subset of records (STORY-0036)
- [ ] A burndown tile shows remaining points or items for an epic, phase or project against an ideal line (STORY-0037)
- [ ] Tiles can chart tracker records when the tracker is available (STORY-0038)
- [ ] The example project opens with a Bugs dashboard and a Backlog dashboard (STORY-0039)
