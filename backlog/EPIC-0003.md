They serve as template for what we do here.
- System settings: add custom schemas (createTable) per ticket-type
- Make existing fields (all but the really mandatory) hidable / functions disableable
- Support Enums (Choice) as datatype
- all must integrate in filters/search, columns are optionally to be shown in the views

## Acceptance criteria

- [ ] A project can give any record type its own fields, including choice (enum) fields, and everyone on the store sees the same schema (STORY-0013)

- [ ] Optional built-in fields can be hidden per type without touching stored values (STORY-0015)
- [ ] Custom fields work in filters, search and as optional list columns (STORY-0016)
