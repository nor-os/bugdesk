## Description

Since last week's release, a handful of users are getting the same
notification email 2-3 times in a row, a few seconds apart. Wasn't happening
before, so this looks like a regression from the recent webhook-retry work
rather than a long-standing issue.

## Comments

### 2026-07-25 · reviewer

Three separate reports in two days, all describing the same "got the same
email 2-3 times" pattern. Timing lines up with the webhook retry logic that
shipped last week — flagging as a likely regression from that change.

### 2026-07-29 · agent

Have a working theory: the new retry loop re-sends the whole notification job
on any non-2xx response from the webhook receiver, including responses that
arrived successfully but timed out client-side before the ack was read. So
the notification actually went out fine, we just didn't get confirmation of
that, and retried anyway. Need to make the retry idempotent — dedupe on a job
id rather than blindly resending — before I'm confident this is fully
understood rather than just plausible. Still digging.
