## Description

Ctrl+S is bound to the app's own save action, but on some browsers the
default "Save page as..." dialog still opens alongside it — looks like the
keydown handler isn't calling `preventDefault()` in every code path.

## Comments

### 2026-06-21 · reviewer

Happens most reliably in Firefox; haven't managed to trigger it in Chrome.

### 2026-06-28 · agent

Found the gap: `preventDefault()` was only being called on the handler
attached to the main editor pane, but Ctrl+S was also reachable while focus
was on the sidebar or the title field, where a second, older handler didn't
have the guard. Added `preventDefault()` to that path too and removed the
duplicate handler entirely — one keydown listener at the document level now
owns Ctrl+S regardless of focus.

### 2026-07-01 · reviewer

Confirmed fixed in Firefox. Closing.

### 2026-07-10 · reviewer

Reopening — a user on Firefox ESR (an older release channel) reported the
browser dialog is back. Looks like the fix works on current Firefox but not
that older build.

### 2026-07-11 · agent

Confirmed: Firefox ESR fires the keydown event with a slightly different
timing relative to the browser's own save-page handler, so `preventDefault()`
was arriving one tick too late on that specific build. Moved the listener to
capture phase instead of bubble phase, which fires early enough on every
Firefox version I could test, including ESR.

### 2026-07-12 · reviewer

Verified on Firefox ESR this time too. Closing again — hopefully for good.
